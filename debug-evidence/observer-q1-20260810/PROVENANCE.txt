METHOD
------
Generator emits BLE-format packet PAIRS: A (len=20, txtag=1) then B (len=30,
txtag=2), asymmetric lengths so the two packet CLASSES are distinguishable (A/B
are two classes from ONE generator -- pair membership, NOT two endpoints /
near-far, which is Q2);
payload[0..1]=pair id, payload[2]=txtag. The A->B END->START gap G is timed
ENTIRELY in hardware (TIMER10 compare -> RADIO TXEN via DPPI); TX ramp-up
cancels in CC_B-CC_A = airtime_A + G. Ladder G in {150,100,70,52} us, 200
pairs each, emitted ROUND-ROBIN (interleaved, not blocked) so no rung is a
contiguous time block; the 150 us rung is the unreduced-tIFS control. Each
pair is self-timestamped (TX ADDRESS of B minus TX PHYEND of A -> gap_gen).
Observer passively captures on the same channel, hardware-timestamping every
packet's ADDRESS/END via PPI 26/27 -> TIMER0 (16 MHz), and dumps all records.

GROUND TRUTH (and a corrected reference -- disclosed)
-----------------------------------------------------
The clean ground truth is the COMMANDED on-air gap: CC_B-CC_A is exact
hardware, so the observer's ADDRESS-to-END span should read G*16 + 640 ticks
(640 = 1M preamble+AA = 5 bytes x 8 us x 16), offset by the observer's own
Q0-measured ADDRESS-vs-END capture bias of -1 tick.

CORRECTION (made AFTER the first Q1 run, disclosed for review): the frozen
protocol named the generator self-timestamp gap_gen as the primary fidelity
reference "to avoid assuming a constant." The data showed gap_gen is NOT a
clean reference -- it carries the generator's OWN fixed TX PHYEND-vs-ADDRESS
capture-latency artifact (a constant ~-50 ticks vs commanded, identical on all
four rungs). Using an uncalibrated second instrument as ground truth was the
error. Primary fidelity is therefore observer-span vs COMMANDED; gap_gen is
kept only as an inter-instrument constant-offset consistency check.

Two REFERENCE-INDEPENDENT facts already establish the core result, needing no
reference choice at all:
  * IQR = 0 on every rung -- the observer's span shows NO observed spread at 62.5 ns
    resolution (every one of 200 pairs measured the identical value;
    sub-tick jitter is unresolved).
  * Rung-to-rung DELTAS = commanded exactly (150->100->70->52 measured
    3039->2239->1759->1471; deltas 800/480/288 ticks = 50/30/18 us x 16),
    which involves no absolute reference.
