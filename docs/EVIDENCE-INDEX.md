# EVIDENCE-INDEX — what we measured, its status, and where the proof + recipe live

**Read this before claiming any result is measured / done / accepted — and before re-running one.**
It exists because status lives in ~88 date-stamped `debug-evidence/` dirs with cryptic names and
inconsistent headers; without an index, "recalling" a result means trusting a lossy one-liner and
silently working from whichever dir you happened to open. That failure mode is real and has recurred.

**Golden rule:** never state a result's status or completeness from memory — find its row here, then
open the cited dir and read its own `FINDINGS.md`/`manifest.json` before you rely on it. The status
words below are read from each dir's actual disposition, **not** a keyword grep (a first-token scan
mislabels these — e.g. it calls `q3-2m-smoke` "open" when it is QUARANTINED).

**How this relates to the other docs:**
[`LESSONS.md`](LESSONS.md) = what *not* to re-assert (traps/retractions). This file = the full
inventory: every result, its true status, whether a runnable recipe exists, and the caveat. README =
the load-bearing headline claims (mapped to their dirs below). REPRODUCE.md = the how-to.

**⚠ NESTED-DIR BLIND SPOT (2026-09-07):** this ledger enumerated only *top-level* `debug-evidence/*/`
and missed **nested** evidence subdirs — notably the **25.15 h `soak-under-load-20260815/`** buried under
`latency-under-load-20260813/`. When
recalling a result, `grep -r` the whole `debug-evidence/` tree, not just the top level. (This is the
exact "we keep missing things" failure the index exists to prevent — it now has a nested-dir hole.)

**Maintenance (do this or the index rots):** every new `debug-evidence/<dir>` (**including nested
subdirs**) adds a row here as part of the same change; when a run supersedes/retracts another, flip the
older row's status to SUPERSEDED/RETRACTED and name the successor. Mirror any status flip into `LESSONS.md` if it changes
what may be asserted.

**Path placeholders and hashes (2026-10-02):** archived configs/harnesses/logs show `<REPO>`,
`<ZEPHYR_WS>`, `<NCS_WS>`, `<ZEPHYR_SDK>` and `<HOME>` where the author's local absolute paths were.
Recorded hashes (SHA256SUMS, manifests, PROVENANCE) refer to the original bytes; check them with
`python3 tools/scrub-paths.py sha256 <file>`, which reverses the substitution exactly. Tools that
re-hash archived files themselves (the observer ABBA combiners re-verify `firmware/*.config`) must be
run on a copy made with `python3 tools/scrub-paths.py unscrub-tree <evidence-dir> <tmp-dir>`. Commit SHAs of
*this* repository cited inside evidence (e.g. `a27ed8a`, `311d51e`) refer to the private development
history, not the published history.

**Checking every recorded hash (2026-10-05):** `python3 tools/scrub-paths.py verify $(git ls-files '*SHA256SUMS')`
accepts a file when its hash matches the raw bytes, the un-scrubbed bytes, or the un-scrubbed bytes with a
literal `$HOME` reversed (an earlier 2026-09-05 history rewrite put `$HOME` in some text files). Result: 1008
of 1023 listed files verify. Known mismatches (15, none affect a measured result): `v442-benchmark-20260907`
`v442-coc-sink.{hex,config}` (rebuilt after hashing, see its row); 10 `fsu-q3a-20260812` `manifest.json` files,
the `capture-tool.py` copies in `coc-fsu-preflight-20260812` and `latency-under-load-20260813`, and
`uplink-coc-diag-20260812/deconfound-v2/FINDINGS-v2.md` (text edited after hashing during the 09-05
reorganisation; no original survives the history rewrite). Every other firmware image verifies.

## Status legend
`ACCEPTED` passed the frozen acceptance protocol · `CONFIRMED` result holds (ABBA / repeated / strict
non-overlap) but not run through a formal acceptance gate · `RESOLVED` question answered ·
`PASS`/`FAIL` a gated control · `QUARANTINED` measured but held (gate bypassed / single capture /
provenance) · `REJECT` failed a structural gate · `RETRACTED`/`SUPERSEDED`/`INVALID`/`WITHDRAWN` do
not cite as-is (see note) · `OPEN` clean number not obtained · `INSTRUMENT-BRINGUP` tooling/spec, not
an evidentiary cell.
